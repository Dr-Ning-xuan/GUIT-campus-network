# GUIT 校园网一键联网

一个给校园网 Web 认证门户用的 Windows 桌面小工具。填好账号密码，点一下就连上；
验证码自动识别，断网自动重连，可以缩在托盘里常驻。

> 纯 HTTP 协议实现，**不驱动浏览器**：直接取验证码图片 → 离线 OCR → POST 表单。


<sub>未联网 / 已联网 / 联网失败 三种状态右侧会切换不同立绘</sub>

## 功能

- **验证码离线识别**：登录页现在是**算式题**（`61加5=?`、`63÷7=?` 这种，运算符还有中文），
  程序识别算式、自己算结果再提交；认错了自动换一张重试（默认最多提交 10 次）
- **识别不出来也不会卡死**：自动认不出时会弹窗把那张算式图摆出来，主人自己填一下照样能连上
- **错误停手保护**：账号/密码这类硬错误立刻停止，不会反复重试把账号锁掉
- **断网自动重连**：后台按设定间隔轮询，掉线自动补登录
- **开机自启 + 托盘常驻**：启动即最小化到托盘，不占任务栏
- **一键断开**：需要切换账号时直接注销当前认证
- **界面状态**：显示当前 IP、在线状态、登录日志；右下角立绘随状态切换（未联网 / 已联网 / 联网失败）
- **网络测速入口**：一键打开测速页面

## 工作原理

适配的是 ASP.NET WebForms 的认证门户（IIS + `.aspx`）。关键点：

- 每次 POST 都要带上**上一次 GET** 里拿到的 `__VIEWSTATE`、`__VIEWSTATEGENERATOR`、
  `__VIEWSTATEENCRYPTED`、`__EVENTVALIDATION`，外加同一会话的 Cookie
- 验证码是独立接口，**每次请求都重新生成**，所以必须"取图 → 识别 → 立刻提交"，不能缓存
- 门户上有**两套验证码**，接口和形态都不一样，不能混用：

  | 页面 | 接口 | 形态 | 怎么填 |
  | --- | --- | --- | --- |
  | 登录 | `/ACaptcha.ashx` | 200×60 算式题，如 `61加5=?`、`63÷7=?` | 填**计算结果** |
  | 注销 / 查询 | `/CheckCode` | 80×24 四位字母数字 | 照抄 |

  老版本程序一直从 `/CheckCode` 取登录验证码，所以门户换成算式题之后就全错 —— 这是 v1.3.0 修的主要问题。
- 服务端**先校验验证码、再校验密码长度**；密码有长度上限
- 失败和成功**都返回 HTTP 200**，只能靠页面文本判断

登录字段（可按自己学校的门户调整）：

```
__VIEWSTATE / __VIEWSTATEGENERATOR / __VIEWSTATEENCRYPTED / __EVENTVALIDATION
ctl00$MainContent$TextBoxISP   运营商（默认 自动选择）
SSOGUITID                      学(工)号（≤12 位）
SSOACC                         上网账号（≤12 位）
SSOPWD                         密码（≤16 位）
TextBoxCC                      验证码（算式结果，最多 4 位）
CheckBoxSaveMe / LoginBtn      记住我 / 登录
```

在线状态从注销页读取，页面里会给出「当前用户 IP」和「已联网 / 未联网」。

### 判断成败的一个坑

有的门户会把自己渲染的成功提示也塞进 `<p class="validation-summary-errors">` 里，
只看这个 class 会把成功当失败。这里的做法是**失败词优先**：
先匹配一批失败关键词（失败 / 错误 / 拒绝 / 无效 / 超时 / 未开通 / 欠费 / 并发 / 已在线 / …），
没有命中失败词、且出现成功词（成功 / 已联网 / 上线）才判定成功。

## 配置

程序同目录的 `config.json`（**明文保存密码**，注意别把这个文件发出去）：

```json
{
  "base_url": "http://10.6.6.6",
  "gui_id": "学工号",
  "account": "上网账号",
  "password": "密码",
  "isp": "自动选择",
  "auto_reconnect": true,
  "auto_connect_on_start": true,
  "poll_seconds": 15,
  "autostart": true,
  "save_credentials": true,
  "manual_captcha": true,
  "max_captcha_retry": 10
}
```

- `manual_captcha`：自动识别不出来时弹窗让主人手输（**默认开着**，算式题本来就不好认）
- `max_captcha_retry`：最多提交几次验证码，默认 10。认不出算式的图只换图不提交，所以实际会看更多张图
- 取消勾选「保存账号密码」时，`gui_id` / `account` / `password` 三个 key 会从文件里**整个删掉**，
  下次启动回落到默认值，而不是留一个空密码
- `config.json`、`_boot.log`、`_selftest.log` 写完后会自动加上**隐藏属性**，不碍眼

## 打包形态怎么选

| | 文件夹版 `--onedir` | 单文件版 `--onefile` |
| --- | --- | --- |
| 体积 | 约 380 MB（600+ 个文件） | 约 188 MB |
| 启动 | 秒开 | 每次启动都要解压到 `%TEMP%`，慢几秒 |
| 开机自启 | 推荐 | 解压期间会让人以为没启动 |
| 对 `%TEMP%` 的要求 | 无 | 需要可写；权限受限时会静默退出 |

**结论**：要开机自启就用文件夹版；单文件版适合临时拷给别人用。

## 常见问题

**Q：双击了没反应 / 关了之后再打不开？**

两种情况先分清楚：

1. **程序其实还在跑**。点右上角 × 默认只是**收进托盘常驻**，进程没退。
   以前这时候再双击，单实例锁会直接静默退出 → 看起来就是"打不开"。
   **v1.3.0 起已修**：再次双击会通过**命名事件**通知已经在跑的那份，
   让它自己把窗口恢复、置顶、激活（不是拿 Win32 硬拉，所以不会出现白窗）；
   万一对面是老版本或事件没送到，才退回去用 `ShowWindow` + 强制重绘兜底，
   两条路都失败时还会弹一句话提示去托盘里看。
2. **单文件版真的起不来**。PyInstaller 单文件版每次启动都要把 385 MB 解到 `%TEMP%\_MEIxxxx`，
   如果以前崩过/被强杀过，这些目录会残留堆积（实测机器上积了 66 个），
   bootloader 清理它们时可能卡住或失败，表现就是**双击没反应、要等很久**。
   清一下就干净了：

   ```powershell
   Remove-Item "$env:TEMP\_MEI*" -Recurse -Force -ErrorAction SilentlyContinue
   ```

   **想彻底躲开这个坑就用文件夹版**（桌面那个带 `_internal` 的），它不解压、秒开、永不残留。

**Q：验证码老认错？**
登录页那套算式题干扰很重（彩色曲线、虚影背景字、满屏圆点），单张图认不准是常态。
程序会一直换图重试，认不出算式的图**只换图、不提交账号**，所以不会拿账号去撞。
实在认不出会弹窗把图摆出来让主人手填 —— 看一眼、敲个数字就能连上。

想自己量一下识别率：

```powershell
.venv\Scripts\python.exe tools\captcha_bench.py --count 20 --verify
```

`--verify` 会用假账号真提交一次，按服务端的「验证码错误!」判定对错，
测的是**真正能用的准确率**；不加就只统计"能认出多少题"。

**Q：开机自启没反应？**
先确认注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里有对应的项，
再看任务管理器 → 启动应用里有没有被禁用。如果用的是单文件版，
启动时要在 `%TEMP%` 里解压，慢几秒是正常的。

**Q：单文件版双击没反应？**
看看 exe 旁边有没有生成 `_boot.log`。如果启动器报
`Could not create temporary directory!`，说明 `%TEMP%` 不可写，换文件夹版即可。

## 更新日志

### v1.3.1（提高识别率）
v1.3.1 抓了 60 张真图**逐张人工标注**（每张的正确答案都写进 `_eval/labels60.json`），
之后所有调参都用这一套样本量，不再靠感觉：

| 版本 | 认出率 | 认出后算对 | **单图可用** | 单张耗时 |
| --- | --- | --- | --- | --- |
| v1.3.0 | 45% | 18% | **8%** | 1.07 s |
| v1.3.1 | 78% | 55% | **43%** | 0.47 s |

- **单图可用率 5 倍**，速度还快了 2 倍多（三线程并行）
- 换一批全新的 120 张再跑：**认出 95/120 = 79%**，55.7 s（0.46 s/张），与标注集一致
- 剩下的错误集中在两类：**除号被认成减号**（`15÷5` 读成 `15-5`）、
  **中文运算符被认成数字**（`9加2` 读成 `94+2`）。这两类预处理救不了，靠重试兜。

再用假账号走真门户又量了 40 张（两轮各 20 张），这一轮带上了票数过滤：

| 指标 | 数字 |
| --- | --- |
| 认出算式 | 29/40 = **73%** |
| 真的提交出去 | **11 次**（其余 18 张认不出或票太少，直接换图） |
| 提交后服务端说验证码对 | 6/11 = **55%** |
| 同样 20 张不带过滤那轮 | 认出 12 张 → 提交 12 次 → 对 4 次 = **33%** |

也就是说：**少交了将近一半的请求，通过率反而从三成抬到五成五**。

所以重试次数是 10 次，并且把三种情况**分开计数**：
认不出、票太少，都只换图不消耗提交次数；只有真的答错才算一次。
10 次全错的概率按 55% 算约 `0.45^10 ≈ 0.03%`。
### v1.3.0（校园网门户换验证码了）

这一版只为了一件事：门户把登录验证码换了，把「一键联网」重新变回一键。

#### 一、根因：登录页的验证码换接口 + 换题型

| | 旧版程序一直在用 | 门户现在实际用的 |
| --- | --- | --- |
| 接口 | `/CheckCode` | **`/ACaptcha.ashx`** |
| 尺寸 | 80×24 | 200×60 |
| 内容 | 4 位字母数字 | `61加5=?`、`63÷7=?` 这类算式 |
| 填什么 | 照抄那 4 个字符 | 填**计算结果** |


铁证是登录页自己的 HTML：`title="请输入此验证码计算结果,点击刷新"`，`src="/ACaptcha.ashx"`，
输入框 `maxlength="4"`。

#### 二、识别：多预处理 × 多模型投票

- **12 个变体**：6 档二值化阈值（150/160/165/170/175/180）× 2 档放大（3×/4×），
  每档先做 2×2 开运算把圆点和 1px 细线滤掉
- **3 个模型**：ddddocr 默认 / `old` / `beta`
- 一共 36 次识别，把能解析成**唯一 `A op B`** 的答案收集起来投票，票数最高者胜
- 只收「能求值」的结果：**除不尽、负数、超过 4 位**一律当成认错丢掉
- 中文运算符 `加 减 乘 除` 与符号 `+ - × ÷` 会混着出，
  `×/x/X`、`÷//`、`一/-` 都做了归一化；识别结果里出现**两个以上运算符**直接判认错
- 认不出来就**换图**，绝不拿账号去撞

#### 三、实测数据（不吹）

用假账号走「提交 → 看服务端反馈」的闭环量出来的：

- **单张**：认出算式约 **50%**，认出后算对约 **33%**，**单张可用率约 17%**，约 0.9~1 s/张
- **端到端**：连续 5 次尝试**全部通过**，耗时 3.2 s / 7.3 s / 7.5 s / 15.5 s

所以重试次数从 6 提到 10，并且把「认不出」和「答错」**分开计数**：
认不出的图只换图，不消耗提交次数。

#### 四、白嫖式验收法（这次新发现，很有用）

用假账号提交，服务端会把两种结果分得很清楚：

- 验证码**错** → `<p class="validation-summary-errors">验证码错误!</p>`
- 验证码**对** → 进入账号校验，回「用户未实名注册运营商上网账号!」之类

**不需要真实账号就能量出识别准确率**，`tools/captcha_bench.py --verify` 就是这么干的。

#### 五、新增功能

- **手动兜底**：自动识别彻底失败时弹窗，把一张新算式图摆出来，填个结果照样能连上
  （`manual_captcha`，默认开）
- **压测工具升级**：`tools/captcha_bench.py` 支持 `--kind math/old` 与 `--verify`

#### 六、修复（第二波，验收时发现的）

- **关了之后再双击打不开**：点 × 只是收进托盘常驻，进程没退、单实例锁还在；
  再双击时旧代码 `print` 一句就 `return 0`，而 `--windowed` 没有控制台
  → 用户看到的就是"双击没反应"
- **单文件版双击没反应**：`%TEMP%` 里堆了 **66 个 `_MEI*` 残留目录**（历史崩溃留下的），
  PyInstaller bootloader 清理/创建临时目录时卡死
- **唤醒出来的窗口一片空白**：第一版用 `EnumWindows` + `ShowWindow(SW_RESTORE)`，
  只拉出了 **Win32 的外框**，Qt 内部仍认为自己是隐藏状态，**一个字都不画**，
  得再点一次任务栏才重绘

#### 七、修复（第三波，窗口唤出改成进程间通知）

- 新增 `src/wakeup.py`：常驻实例创建**命名事件** `Local\GUITCampusAutoLoginShow`，
  用 250 ms 的 `QTimer` 监听；新实例 `SetEvent` 敲一下门就退出
- 老实例收到后**自己调 `showNormal()` + `raise_()` + `activateWindow()`**
  —— 走 Qt 自己的显示路径，内容才是完整的，根除白窗
- 兜底路径（对面是老版本 / 事件没送到）补上
  `SetWindowPos` + `InvalidateRect` + `UpdateWindow`，强制把窗口重画一遍

#### 八、配置变更

- `manual_captcha` 默认 `false` → **`true`**（算式题不好认，没有兜底太容易卡死）
- `max_captcha_retry` 默认 `6` → **`10`**

#### 九、保留

- 注销 / 查询页还是 `/CheckCode` 那套四位字母数字，原来的识别器继续用

  托盘可能几十秒才出现，容易被误认为「自启没生效」（实测文件夹版 0.8 秒、单文件版 3.9 秒）。
  程序启动时还会自动把指向单文件版的旧自启项纠正过来。
