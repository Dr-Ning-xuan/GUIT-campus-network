# GUIT 校园网一键联网

一个给校园网 Web 认证门户用的 Windows 桌面小工具。填好账号密码，点一下就连上；
验证码自动识别，断网自动重连，可以缩在托盘里常驻。

> 纯 HTTP 协议实现，**不驱动浏览器**：直接取验证码图片 → 离线 OCR → POST 表单。


<sub>未联网 / 已联网 / 联网失败 三种状态右侧会切换不同立绘</sub>

## 功能

- **验证码离线识别**：登录页现在是**算式题**（`61加5=?`、`63÷7=?` 这种，运算符还有中文），
  程序识别算式、自己算结果再提交；认错了自动换一张重试（默认最多提交 10 次）
- **识别不出来也不会卡死**：自动认不出时会弹窗把那张算式图摆出来，主人自己填一下照样能连上
- **错误停手保护**：账号/密码这类硬错误立刻停止，不会反复重试把账号锁掉
- **断网自动重连**：后台按设定间隔轮询，掉线自动补登录
- **开机自启 + 托盘常驻**：启动即最小化到托盘，不占任务栏
- **一键断开**：需要切换账号时直接注销当前认证
- **界面状态**：显示当前 IP、在线状态、登录日志；右下角立绘随状态切换（未联网 / 已联网 / 联网失败）
- **网络测速入口**：一键打开测速页面

## 工作原理

适配的是 ASP.NET WebForms 的认证门户（IIS + `.aspx`）。关键点：

- 每次 POST 都要带上**上一次 GET** 里拿到的 `__VIEWSTATE`、`__VIEWSTATEGENERATOR`、
  `__VIEWSTATEENCRYPTED`、`__EVENTVALIDATION`，外加同一会话的 Cookie
- 验证码是独立接口，**每次请求都重新生成**，所以必须"取图 → 识别 → 立刻提交"，不能缓存
- 门户上有**两套验证码**，接口和形态都不一样，不能混用：

  | 页面 | 接口 | 形态 | 怎么填 |
  | --- | --- | --- | --- |
  | 登录 | `/ACaptcha.ashx` | 200×60 算式题，如 `61加5=?`、`63÷7=?` | 填**计算结果** |
  | 注销 / 查询 | `/CheckCode` | 80×24 四位字母数字 | 照抄 |

  老版本程序一直从 `/CheckCode` 取登录验证码，所以门户换成算式题之后就全错 —— 这是 v1.3.0 修的主要问题。
- 服务端**先校验验证码、再校验密码长度**；密码有长度上限
- 失败和成功**都返回 HTTP 200**，只能靠页面文本判断

登录字段（可按自己学校的门户调整）：

```
__VIEWSTATE / __VIEWSTATEGENERATOR / __VIEWSTATEENCRYPTED / __EVENTVALIDATION
ctl00$MainContent$TextBoxISP   运营商（默认 自动选择）
SSOGUITID                      学(工)号（≤12 位）
SSOACC                         上网账号（≤12 位）
SSOPWD                         密码（≤16 位）
TextBoxCC                      验证码（算式结果，最多 4 位）
CheckBoxSaveMe / LoginBtn      记住我 / 登录
```

在线状态从注销页读取，页面里会给出「当前用户 IP」和「已联网 / 未联网」。

### 判断成败的一个坑

有的门户会把自己渲染的成功提示也塞进 `<p class="validation-summary-errors">` 里，
只看这个 class 会把成功当失败。这里的做法是**失败词优先**：
先匹配一批失败关键词（失败 / 错误 / 拒绝 / 无效 / 超时 / 未开通 / 欠费 / 并发 / 已在线 / …），
没有命中失败词、且出现成功词（成功 / 已联网 / 上线）才判定成功。

## 配置

程序同目录的 `config.json`（**明文保存密码**，注意别把这个文件发出去）：

```json
{
  "base_url": "http://10.6.6.6",
  "gui_id": "学工号",
  "account": "上网账号",
  "password": "密码",
  "isp": "自动选择",
  "auto_reconnect": true,
  "auto_connect_on_start": true,
  "poll_seconds": 15,
  "autostart": true,
  "save_credentials": true,
  "manual_captcha": true,
  "max_captcha_retry": 10,
  "min_votes": 5
}
```

- `manual_captcha`：自动识别不出来时弹窗让主人手输（**默认开着**，算式题本来就不好认）
- `max_captcha_retry`：最多提交几次验证码，默认 10。认不出算式的图只换图不提交，所以实际会看更多张图
- `min_votes`：识别结果的票数低于这个数就**不提交**、直接换图，默认 5。
  验证码是 session 绑定的，换图后旧答案就作废，所以只有「现在交」和「放弃」两条路；
  实测票 ≥5 的答案正确率约 55~60%，票 <5 的只有三成，宁可贵一张图。设 0 关掉这层过滤
- 取消勾选「保存账号密码」时，`gui_id` / `account` / `password` 三个 key 会从文件里**整个删掉**，
  下次启动回落到默认值，而不是留一个空密码
- `config.json`、`_boot.log`、`_selftest.log` 写完后会自动加上**隐藏属性**，不碍眼

## 常见问题

**Q：双击了没反应 / 关了之后再打不开？**

两种情况先分清楚：

1. **程序其实还在跑**。点右上角 × 默认只是**收进托盘常驻**，进程没退。
   以前这时候再双击，单实例锁会直接静默退出 → 看起来就是"打不开"。
   **v1.3.0 起已修**：再次双击会通过**命名事件**通知已经在跑的那份，
   让它自己把窗口恢复、置顶、激活（不是拿 Win32 硬拉，所以不会出现白窗）；
   万一对面是老版本或事件没送到，才退回去用 `ShowWindow` + 强制重绘兜底，
   两条路都失败时还会弹一句话提示去托盘里看。
2. **单文件版真的起不来**。PyInstaller 单文件版每次启动都要把 385 MB 解到 `%TEMP%\_MEIxxxx`，
   如果以前崩过/被强杀过，这些目录会残留堆积（实测机器上积了 66 个），
   bootloader 清理它们时可能卡住或失败，表现就是**双击没反应、要等很久**。
   清一下就干净了：

   ```powershell
   Remove-Item "$env:TEMP\_MEI*" -Recurse -Force -ErrorAction SilentlyContinue
   ```

   **想彻底躲开这个坑就用文件夹版**（桌面那个带 `_internal` 的），它不解压、秒开、永不残留。

**Q：验证码老认错？**
登录页那套算式题干扰很重（彩色曲线、虚影背景字、满屏圆点），单张图认不准是常态。
程序会一直换图重试，认不出算式的图**只换图、不提交账号**，所以不会拿账号去撞。
实在认不出会弹窗把图摆出来让主人手填 —— 看一眼、敲个数字就能连上。

想自己量一下识别率：

```powershell
.venv\Scripts\python.exe tools\captcha_bench.py --count 20 --verify
```

`--verify` 会用假账号真提交一次，按服务端的「验证码错误!」判定对错，
测的是**真正能用的准确率**；不加就只统计"能认出多少题"。

**Q：开机自启没反应？**
先确认注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里有对应的项，
再看任务管理器 → 启动应用里有没有被禁用。如果用的是单文件版，
启动时要在 `%TEMP%` 里解压，慢几秒是正常的。

**Q：单文件版双击没反应？**
看看 exe 旁边有没有生成 `_boot.log`。如果启动器报
`Could not create temporary directory!`，说明 `%TEMP%` 不可写，换文件夹版即可。

## v1.6.0 —— 彻底移除 ddddocr，两个模型全自训

### 新增

- **自训四位字母数字 CRNN**（`src/crnn4_ocr.py` 的 `Crnn4Solver`）
  - 输入 32×128（原生 80×24 RGBA），字符集 36 类 `0-9A-Z` + blank
  - 训练数据 10,599 张：raw4 两引擎一致 3,184 + raw4b 三票一致 7,415
  - 20 轮，最佳 val **98.11%**（上一版 92.77%）
  - int8 weight-only，**4.18 MB**
- **150 张人工标注验收集**（`label4_100` + `label4_50`），刻意排除在训练之外
- **三票预标注流水线**：自训模型 + ddddocr old + ddddocr slim 三引擎并行，
  三票一致 75.2%（7,516/10,000），作为训练集；两票/一票的 2,484 张留给后续人工

### 移除

| 移除项 | 打包占用 | 移除理由 |
|---|---|---|
| `common_slim.onnx` | 18.36 MB | 算式旧兜底，CRNN 已接管 |
| `common_old.onnx` | 6.46 MB | 4 位官方模型，被 captcha4 替代 |
| `ddddocr` 包本体 | 0.15 MB | 两个模型都不再需要 |
| `MathCaptchaSolver` 的 ddddocr 回退分支 | — | 加载失败改为直接抛错，不再假装能救 |
| `_install_cv2_stub` 的运行时必要性 | — | 只服务 ddddocr 的 cv2 硬 import |

### 修复

- **自检文案造假**：`main.py` 里一直打印 `[selftest] ddddocr 4位 OK`，
  实际早就不走 ddddocr 了。改为打印真实类名（`Crnn4Solver`）
- **测试与产物脱节**：`test_portal.py` 拿 `CaptchaSolver(length=4)` 测 `normalize`，
  测试里 ddddocr 还在、产物里已经没了。改用 `Crnn4Solver`
- **spec 打包整个 models/ 目录**：备份和实验模型会被一起打进去。改为逐文件列举

### 提升

|---|---|---|---|
| **exe 体积** | 82.75 MB | **60.92 MB** | −21.83 MB（−26%） |
| **4 位准确率**（150 张人工） | 71.3%（ddddocr old） | **96.0%** | **+24.7 pt** |

## v1.5.1 —— 换自训 CRNN，算式识别从 36% 到 66%

### 新增

- `src/crnn_ocr.py` 的 `CrnnSolver`：21 类 CRNN（`0-9 + - × ÷ = ? 加减乘除`）
  - 骨干 64/128/256/256 + BiLSTM 256，约 620 万参数，输入 **96×320**
  - 训练数据：4.5 万张/轮几何增广合成图 + 2.3 万张真图（ddddocr ≥5 票自举）
  - 11 epoch / RTX 5060 / 49 分钟，导出 int8 **6.3 MB**
- `single_shot` 机制：`CrnnSolver.single_shot = True`，`service.py` 见到它直接把票数门槛强制归零

### 移除

- 算式识别不再用 ddddocr 的多引擎投票（72 类字符集里没有 `÷`，除法 30 张全错）

### 修复

- **票数门槛在升级后仍然生效**：老用户 `config.json` 里存着 3 或 5，
  结果每张图都被判「票太少不提交」，一路换到第 30 张才被迫提交最差的那张。
  现在由 `single_shot` 强制归零，老配置不用改

### 提升

| 指标 | v1.4.3（ddddocr） | v1.5.1（CRNN） | 变化 |
|---|---|---|---|
| 单图算对 | 36.0% | **66.0%** | +30.0 pt |
| ＋ | 43.8% | 50.0% | +6.2 |
| － | 33.3% | 59.3% | +26.0 |
| × | 76.9% | 69.2% | **−7.7** |
| ÷ | 0.0% | **80.0%** | +80.0 |
| 单张耗时 | ~1002 ms | **20 ms** | 快 50× |

**代价**：78.1 → 82.7 MB（模型 4.5 → 6.3 MB）。

### 已知缺陷

- 个位题（＋ 类）只有 50%，典型是 `77+0` 读成 `7+0`（首字符被 CTC 吃掉）
- `×`/`÷` 偶有混淆

## v1.4.3 —— 认出率 67% → 80%

### 新增

- 2× 放大档（小图放大后模型对粘连字符分辨更好）
- 早停：3× 那批票数够了直接返回

### 修复

- **变体分配导致结果漂移**：以前 24 个变体按 `i % 2` 分给两个模型，
  同一变体只有一个模型看过，认出率随变体顺序在 71%~79% 浮动。
  改成两个模型都看每个变体，票数翻倍、结果确定

### 提升

- 认出率 67% → **80%**
- 5 张内登录成功 89% → **94%**
- ≥5 票的图 33 → **60 张**
- 平均每张 737 ms

  cv2 不存在时直接抛 ImportError。往 `sys.modules` 塞空壳让它平安过去

### 修复

- **形近字母还原**：ddddocr 常把 1 认成 I、0 认成 O、5 认成 S，
  老代码 `_STRIP_RE` 一律剥掉字母 = 把数字吃掉了。改为只收大写还原
  （小写 l/i 绝不能碰，它们多半是「加」「减」被认歪的偏旁）
- **拒绝前导零**：`8-02` 这种题门户不会出，出现基本是多认了一位

### 提升

- 189.1 → **129.6 MB**（−31%）
- 冷启动 6.9 s → **3.4 s**
- 单张识别 464 ms → **301 ms**
- 离线 60 张认出率 78% → **82%**

### 试过但没用（别再试）

- 裁剪窗口右移：认出率涨到 83%，但**服务端通过率从 53% 掉到 44%** —— 多认出来的基本是多认了一位
- 连通域分割：块数分布 {2:1, 3:8, 4:7, 5:7, 6:5, 7:1, 8:1}，干扰线把字连成一片，切不齐

## v1.3.1 —— 把识别率从 8% 拉到 43%

### 新增

- 「更新地址」按钮（开浏览器到 GitHub 仓库）
- 托盘加固：唤出时确认图标还在、托盘不可用写日志
- **7 个调参工具**：`grab_captcha` / `montage` / `eval_offline` / `score` / `exp_ocr` / `debug_one` / `peek_variants`

### 修复

三处根因：

1. **二值化用错通道**：原来按「RGB 最大通道 < 阈值」取前景，
   深蓝/深紫字符 B 通道 200+ 被判成「亮」丢掉。换成感知亮度
   `0.299R+0.587G+0.114B` 后，深色字符（灰度 100~160）与亮彩色干扰（190~230）一下分开了
2. **右边 `= ?` 被一起喂给模型**：问号在不少字形里就是个「2」，
   `8乘6=?` 被读成 `8*62 = 496`
3. **没裁边**：200×60 里字符只占中间一小块，缩放后只有二十几像素高

### 提升

| 指标 | v1.3.0 | v1.3.1 |
|---|---|---|
| 认出率 | 45% | **78%** |
| 单图可用 | 8% | **43%** |
| 单张耗时 | 1.07 s | **0.47 s** |

- 换一批全新 120 张复测：认出 **95/120 = 79%**，两批数字对得上
- 假账号走真门户 40 张：认出 73%，提交 11 次，服务端认 6 次 = **55%**
  （不带票数过滤那轮：提交 12 次只对 4 次 = 33%）

## v1.3.0 —— 门户换验证码了

### 新增

- **支持 `/ACaptcha.ashx` 算式验证码**（原来是 `/CheckCode` 的 4 位字母数字）
- 32 个预处理变体 × 3 个模型 = 96 次识别，三线程并行

- 压测工具 `captcha_bench.py` 支持 `--kind math/old` 与 `--verify`

### 修复

- **关了之后再双击打不开**：点 × 只收进托盘，进程没退、单实例锁还在，
  再双击时旧代码 `print` 一句就 `return 0`，而 `--windowed` 没有控制台 → 用户看到「双击没反应」
- **单文件版双击没反应**：`%TEMP%` 里堆了 **66 个 `_MEI*` 残留目录**，
  PyInstaller bootloader 清理/创建临时目录时卡死
- **唤醒出来的窗口一片空白**：`EnumWindows` + `ShowWindow` 只拉出 Win32 外框，
  Qt 内部仍认为自己是隐藏状态，一个字都不画

### 提示

- 根因是**从源头就取错了**：老版本拿的是注销页那张图，和登录页的答案根本不是一回事
